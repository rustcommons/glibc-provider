# glibc-provider-sources v0.1.0

The first published `glibc-provider-sources` library lets source-provider consumers
read and extract the glibc inputs needed to build startup objects, nonshared
archives and link stubs locally, without receiving compiled glibc objects.

Originally published to crates.io on **2026-10-13** (non-yanked at the
2026-11-02 inspection). Source tag `v0.1.0` identifies commit
`1ae578cf7123399b0c710f44defab93cc2021001`. These notes were reconstructed on
2026-11-02; GitHub Release documentation is a later backfill, not a new crate
publication or an assertion that these notes existed at the tag.

## Changes

- Records all 28 x86_64 glibc releases from 2.17 through 2.44: exact source inputs,
  generated and installed headers, compile commands, builder defaults, object
  interfaces and public definitions of eight shared libraries. This supports
  source delivery without shipping compiled glibc provider objects.
- Provides the std-only `Sources`/`Release` API and embedded compressed source
  pack, with hash verification and extraction to new directories. The library
  needs no external decompressor or GCC just to read/extract data; local object
  builds require GCC/binutils on x86_64 Linux.
- Includes reviewed accepted differences. The separate collector and replay tools
  are unpublished maintenance tools, not additional released packages.

## Upgrade

For new library consumers, add `glibc-provider-sources = "0.1"` to Cargo.toml
with Rust 1.90 or newer. Application developers should start with cargo-libc,
which coordinates downstream provider use. There is no earlier published provider
library in this repository to migrate from.

The immutable 0.1.0 README incorrectly says the library is unpublished, links
relatively to guides excluded from the package and shows unusable collector
commands/hash placeholder. Use the maintained guides linked below or the
corrected 0.1.1 README. Backfilled notes do not change the old archive.

No fresh Rust suite, collection or replay was run for this documentation backfill.

Registry archive SHA-256:
`62eb50dd168d92ce36af896177c886c7889b1f62f5f09d07d64bedff74dac04e`.
