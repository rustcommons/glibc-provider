# glibc-provider-sources v0.1.1

`glibc-provider-sources` 0.1.1 fixes the published README so readers can identify
the available library, follow a complete setup example and reach its guides.
The API and provider inputs are unchanged from 0.1.0.

Originally published to crates.io on **2026-11-01** (non-yanked at the
2026-11-02 inspection). Source tag `v0.1.1` identifies commit
`2a7a0fafce50b8516208a89c98f7b5023b77ecbf`. These notes were backfilled on
2026-11-02; a later GitHub Release entry documents that existing publication.

## Changes

- The README says the library is published instead of “not yet published”. It
  states Rust 1.90 prerequisites and supplies a complete non-writing Rust example.
- Absolute GitHub URLs replace relative links to guides excluded from the crate.
  Correct collector commands, explicit binary selection and the real pinned-hash
  prerequisite live in the maintenance guide rather than broken README commands.
- No exported API, runtime behavior, source blobs, tables, source pack, accepted
  differences or licenses changed. The unpublished collector remains 0.1.0.

## Upgrade

A `glibc-provider-sources = "0.1"` dependency can resolve 0.1.1. Existing 0.1.0
locks need no refresh for provider behavior; selecting 0.1.1 delivers the corrected
packaged README. No downstream linux-abi-tools or cargo-libc release is required
just to obtain guide-link changes. Rust 1.90 remains the minimum.

The original 0.1.0 archive and README remain immutable. Current repository
changelog/navigation changes are not retroactive edits to either archive.

## Validation and limits

The linked publication record identifies the exact approved merge and records
Rust 1.90 formatting, 28 unit/integration tests, one doctest, warning-denied docs,
pack equality, package verification and execution of the packaged README example.
Clippy passed on CI-pinned Rust 1.99; Clippy 1.90 reported an existing collector
`nonminimal_bool` warning, which was preserved and documented rather than claimed
as a pass. Those checks are bounded historical release evidence, not new tests
for this notes backfill.

The published archive is non-yanked at inspection, contains 18 files, and has
SHA-256 `da10605d1cab20eb0ab8cf7ebe19b619737618578dc8c74e6c62a57e1a7ec440`.
All 13 protected payload files match official 0.1.0 byte for byte. The published
README was inspected in real crates.io/docs.rs renders, and versioned docs.rs
build #5104129 generated the API successfully. No fresh compiler replay matrix
or downstream system qualification is claimed. Tier 3 remains deferred; the
legal gate on prebuilt compiled-provider objects remains in force.
